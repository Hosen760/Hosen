## 3.1 智能体的本质

AI 智能体可以被拆解为两部分：

```text
大模型 + 智能体框架
```

大模型负责理解、推理和生成内容；智能体框架负责组织任务、调用工具、执行程序，并把结果返回给用户。

所谓智能体框架，例如 hermes、openclaw、claude code，本质上是一种程序。这个程序可以借助大模型的能力，完成用户交给它的任务。

更具体地说，智能体框架之所以能完成任务，是因为它可以让大模型参与到实际工作流程中。例如：

1. 理解用户提出的问题；
2. 判断应该使用什么工具；
3. 生成命令行命令、Python 代码或 API 调用；
4. 执行这些程序；
5. 读取程序运行结果；
6. 再让大模型继续分析、总结和生成最终答案。

当然，智能体框架中也会事先集成一些工具，所以并不是所有任务都需要临时写新程序。

例如，我们让智能体分析一个 Excel 表格，表面上看是用户在和 AI 对话，但实际过程很可能是：

```text
用户提出分析需求
  ↓
大模型理解任务
  ↓
智能体生成 Python 代码
  ↓
Python 读取 Excel 并计算
  ↓
程序返回计算结果
  ↓
大模型根据结果生成分析报告
```

这也是为什么在安装许多智能体框架时，通常也需要安装 Python、命令行工具或其他运行环境。

因此，可以这样理解：

> 智能体不是单纯的聊天机器人，而是一个能够调用工具、执行程序、处理文件和完成任务的 AI 工作系统。

换言之，计算机世界里没有魔法。一个任务越能够被程序化、流程化、工具化，智能体就越容易把它做好。

## 3.2 系统整体框架

本系统的整体框架可以简化理解为：

```text
                                    Internet
                                       │
                        ┌──────────────┴──────────────┐
                        ▼                             ▼
              飞书API / MiniMax API            Syncthing Relay
                    (外网中转)                    (外网中转)
                        │                             │
┌───────────────────────▼─────────────────────────────▼───────────────────────┐
│                                局域网路由器                                   │
└──────────┬───────────────────────────┬───────────────────────────┬──────────┘
           │                           │                           │
           ▼                           ▼                           ▼
┌────────────────────┐      ┌────────────────────┐      ┌────────────────────┐
│      用户电脑      │      │     Mac Studio     │      │      群晖 NAS      │
│                    │      │     (15+ Users)    │      │     (存储中心)     │
│  Syncthing 客户端  │      │  Supervisor / Agent│      │   全量知识库 RAID5 │
└──────────┬─────────┘      └──────────┬─────────┘      └──────────┬─────────┘
           │                           │                           │
           └───────────────────────────┼───────────────────────────┘
                                       ▼
                          Syncthing 三方实时双向同步

──────────────────────────────────────────────────────────────────────────────
【业务数据流】
 用户飞书提问 ──> 飞书Bot ──> 路由转发 ──> Mac Studio (专属 Agent 业务处理与响应)

```

其中，各部分的作用如下：

| 模块 | 作用 |
|---|---|
| 用户电脑 | 用户日常使用的设备 |
| 飞书 | 用户和智能体交互的入口 |
| Mac Studio | 智能体运行和任务执行的核心服务器 |
| NAS | 大量资料和知识库的长期存储中心 |
| Syncthing | 在用户电脑、Mac Studio、NAS 之间同步文件 |
| 大模型 | 负责理解任务、生成方案和总结结果 |
| 智能体框架 | 负责调度工具、执行任务和组织流程 |

可以把整套系统理解为：

> Mac Studio 是计算中心，NAS 是存储中心，飞书是使用入口，智能体是执行任务的数字员工。

## 3.3 为什么要把智能体部署在 Mac Studio 上

在这个方案中，我们将智能体部署在 Mac Studio 上，而不是部署在每个用户自己的电脑上，主要有三个原因。

### 3.3.1 Mac Studio 性能更强

智能体在执行任务时，可能需要同时处理：

1. 大量文本；
2. Excel 表格；
3. PDF 文件；
4. Python 数据分析；
5. 多用户并发请求；
6. 本地知识库检索；
7. 长时间运行的自动化任务。

这些任务对内存、CPU、硬盘和网络都有一定要求。

Mac Studio 拥有更强的硬件配置，因此更适合作为集中运行智能体的服务器。

---

### 3.3.2 数据和文件需要统一管理

投研工作中会涉及大量资料，例如：

1. 公司公告；
2. 行业研报；
3. 财务数据；
4. 会议纪要；
5. Excel 表格；
6. 用户上传文件；
7. 智能体生成的报告。

如果这些资料分散在每个用户自己的电脑上，管理和协作都会比较困难。

将文件和知识库集中在 Mac Studio 与 NAS 上，可以让智能体更方便地读取、分析和调用这些资料。

---

### 3.3.3 服务器可以长期稳定运行

用户自己的电脑通常不会 24 小时开机，也不适合长期运行后台任务。

而 Mac Studio 可以作为一台长期在线的工作站，用来执行：

1. 定时生成日报；
2. 定时更新知识库；
3. 定时检查数据；
4. 定时推送市场信息；
5. 后台运行用户任务；
6. 保持多个智能体长期在线。

因此，Mac Studio 更适合作为整个智能体系统的核心。

---

## 3.4 多用户如何使用同一套智能体系统

Mac Studio 只有一台，但用户可以有很多。

所以本系统的设计思路不是让每个用户直接控制 Mac Studio，而是让用户使用 Mac Studio 上提供的智能体服务。

用户只需要通过自己熟悉的方式提出需求，例如：

1. 在飞书中向智能体提问；
2. 把文件放入同步文件夹；
3. 等待智能体处理；
4. 接收返回结果。

对用户来说，使用体验类似于：

```text
我把任务交给一个 AI 助手
AI 助手在服务器上完成任务
然后把结果发回给我
```

用户不需要关心：

1. 智能体运行在哪里；
2. 调用了什么模型；
3. 执行了什么代码；
4. 使用了什么工具；
5. 后台服务如何调度；

这些复杂工作都由系统在后台完成。

## 3.5 系统中建议配置两类智能体

为了让系统更清晰、稳定、可管理，建议配置两类智能体：

```text
User Agent
Supervisor Agent
```

---

## 3.6 User Agent：普通用户的投研助手

User Agent 是面向普通用户的智能体。

它的主要职责是帮助用户完成日常投研工作，例如：

1. 总结研报；
2. 分析 Excel 数据；
3. 整理会议纪要；
4. 生成公司分析报告；
5. 提取 PDF 里的关键信息；
6. 比较不同公司财务指标；
7. 查询和整理知识库资料；
8. 生成图表、表格和文字结论。

可以把 User Agent 理解为：

> 每个用户的专属 AI 投研助理。

例如，用户可以这样使用它：

```text
请帮我总结这份新能源行业研报，重点提取产业链、重点公司和风险因素。
```

```text
请分析这个 Excel 表格中的收入、毛利率和费用率变化。
```

```text
请根据这些资料，写一份公司 A 的初步研究框架。
```

User Agent 的重点不是管理系统，而是帮助用户完成业务任务。

---

## 3.7 Supervisor Agent：系统管理员智能体

Supervisor Agent 是面向管理员的智能体。

它不主要负责投研分析，而是负责帮助管理员理解和维护整个系统。

它可以协助完成：

1. 查看系统运行状态；
2. 查看各个智能体是否正常；
3. 检查任务是否失败；
4. 检查服务器资源占用；
5. 查看同步状态；
6. 生成系统运行报告；
7. 协助排查异常问题；
8. 提醒管理员进行维护。

可以把 Supervisor Agent 理解为：

> 管理所有智能体的 AI 系统管家。

例如，管理员可以问：

```text
请检查今天系统运行是否正常。
```

```text
请查看是否有任务失败。
```

```text
请总结一下今天各用户的使用情况。
```

```text
请检查 Mac Studio 当前资源占用情况。
```

Supervisor Agent 的重点是系统运维，而不是普通投研分析。

## 3.8 智能体完成任务的一般流程

一个智能体完成任务，通常不是一步完成的，而是一个循环过程。

可以简化理解为：

```text
用户提出任务
  ↓
智能体理解任务
  ↓
制定处理计划
  ↓
调用工具执行
  ↓
读取执行结果
  ↓
继续分析或修正
  ↓
生成最终结果
  ↓
返回给用户
```

例如，用户说：

```text
请分析这份公司财务数据。
```

智能体可能会经历以下过程：

1. 判断这是一个数据分析任务；
2. 找到对应的数据文件；
3. 使用 Python 读取表格；
4. 计算收入、利润、毛利率等指标；
5. 生成图表；
6. 分析趋势；
7. 找出异常点；
8. 输出文字结论；
9. 返回分析报告。

所以，智能体的工作并不是简单地“回答问题”，而是：

> 理解任务，然后借助工具一步步把任务做完。

## 3.10 智能体不适合做什么

智能体虽然很有用，但并不是万能的。

它不适合完全替代人类做以下事情：

1. 高风险投资决策；
2. 法律、合规、审计等需要专业责任的判断；
3. 没有数据来源的主观判断；
4. 对准确性要求极高且不能出错的任务；
5. 模糊到无法执行的任务；
6. 需要强现实世界经验的复杂决策。

例如，下面这种问题就不适合直接让智能体给最终结论：

```text
这个项目能不能投？
```

更合适的问法是：

```text
请根据公司年报、行业研报，帮我整理这家公司当前的投资逻辑、风险因素和需要进一步验证的问题。
```

也就是说，智能体更适合作为：

> 研究助理、数据助理、文档助理、自动化助理。

而不是：

> 最终决策者。

## 3.11 用户应该如何更好地使用智能体

为了让智能体更好地完成任务，用户提出需求时应该尽量明确。

不太好的提问方式是：

```text
帮我看看这个文件。
```

```text
分析一下这家公司。
```

```text
给我一个结论。
```

这些问题太宽泛，智能体很难判断应该重点分析什么。

更好的提问方式是：

```text
请分析这个 Excel 文件中的收入、毛利率和费用率变化，并输出一份简洁的分析报告。
```

```text
请总结这份研报，重点提取：
1. 核心观点；
2. 产业链结构；
3. 重点公司；
4. 关键数据；
5. 风险因素。
```

```text
请根据这些资料，帮我整理公司 A 的研究框架，包括：
1. 主营业务；
2. 收入结构；
3. 行业空间；
4. 竞争优势；
5. 风险点；
6. 后续需要验证的问题。
```

总体原则是：

> 用户给出的任务越清楚，智能体完成任务的质量越高。

## 3.12 系统运行中需要注意的问题

虽然系统整体使用起来可以很简单，但后台仍然需要注意一些问题。

### 3.12.1 权限问题

不同用户的数据和任务应该尽量隔离。

普通用户不应该看到其他用户的文件、任务记录或敏感信息。

---

### 3.12.2 成本问题

智能体调用大模型通常会产生费用。

如果多个用户频繁使用，成本可能快速增加。

因此需要关注：

1. 每天的模型调用量；
2. 每个用户的大致消耗；
3. 是否存在异常高频请求；
4. 是否有不必要的大任务。

---

### 3.12.3 资源问题

Mac Studio 虽然性能较强，但资源不是无限的。

当多个用户同时使用时，可能出现：

1. 内存占用过高；
2. CPU 占用过高；
3. 磁盘空间不足；
4. 任务排队；
5. 响应变慢。

因此，需要合理控制并发任务数量。

---

### 3.12.4 数据安全问题

系统中可能会涉及：

1. 公司资料；
2. 投研文件；
3. 财务数据；
4. 用户上传文件；
5. API Key；
6. 系统配置。

这些内容都需要妥善保护。

尤其是 API Key、密码等敏感信息，不应该暴露给普通用户或普通智能体。

---

### 3.12.5 结果可靠性问题

智能体生成的结果可能存在错误。

尤其是在投研场景中，智能体可能会：

1. 理解错数据；
2. 引用不完整；
3. 生成看似合理但实际错误的结论；
4. 混淆不同公司的信息；
5. 对财务指标解释不准确。

因此，智能体输出应该被看作：

> 辅助分析结果，而不是最终结论。

重要报告仍然需要人工复核。

## 3.14 系统建设建议

对于计算机基础不强的团队，不建议一开始就把系统做得过于复杂。

更合理的方式是分阶段建设。

---

### 3.14.1 第一阶段：单用户可用

目标是先让一个用户能够正常使用智能体。

需要实现：

1. Mac Studio 上能运行智能体；
2. 用户能通过飞书提问；
3. 智能体能读取用户提供的文件；
4. 智能体能完成简单文档总结和 Excel 分析。

这个阶段的重点是：

> 先跑通，而不是追求完美。

---

### 3.14.2 第二阶段：多用户可用

当单用户流程稳定后，再扩展到多个用户。

需要实现：

1. 每个用户有自己的智能体；
2. 不同用户之间任务不混乱；
3. 系统可以同时处理多个用户请求；
4. 用户可以稳定收到结果。

这个阶段的重点是：

> 让多人能稳定使用。

---

### 3.14.3 第三阶段：接入知识库

当多用户使用稳定后，可以逐步加入知识库能力。

例如：

1. 行业研报库；
2. 公司公告库；
3. 财务数据资料；
4. 历史会议纪要；
5. 内部研究资料。

这个阶段的重点是：

> 让智能体不只是聊天，而是能够基于已有资料工作。

---

### 3.14.4 第四阶段：加入 Supervisor Agent

当用户和任务越来越多后，就需要系统管理能力。

Supervisor Agent 可以帮助管理员：

1. 查看系统状态；
2. 检查异常任务；
3. 统计使用情况；
4. 生成运行报告；
5. 辅助日常维护。

这个阶段的重点是：

> 降低系统管理成本。

---

### 3.14.5 第五阶段：自动化任务

最后，可以逐步加入自动化任务。

例如：

1. 每日市场简报；
2. 每周行业资料更新；
3. 定时公告监控；
4. 定时生成用户报告；
5. 定时系统巡检。

这个阶段的重点是：

> 让系统从被动回答问题，升级为主动完成工作。
